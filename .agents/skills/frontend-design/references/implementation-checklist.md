# 前端实现检查清单

仅在 Codex Stage 2 进入代码实现或初步检查时读取本文件。根据任务规模选择适用项，不为满足清单而增加无意义复杂度。这里的通过结果只是交给 Antigravity Stage 3 的初步证据，不构成完整验证。

## 1. 排版

- 为 display、body 和可选的 utility/data 角色明确字体与回退栈。
- 避免无理由使用 Arial、Inter、Roboto 或系统默认字体作为主要视觉表达。
- 检查标题、正文、标注的字号、字重、行高、字距和段落宽度。
- 确认 Web Font 加载失败时仍可读，避免字体切换造成严重布局跳动。

## 2. 色彩与主题

- 用 CSS custom properties 管理设计令牌，避免散落的魔法色值。
- 保持主色与强调色职责清晰，不平均分配视觉权重。
- 正文与背景对比度以 WCAG AA 为最低目标：普通文字 4.5:1，大文字 3:1。
- 不只依靠颜色传达状态，同时使用文字、图标、形状或位置。
- 检查 hover、focus、disabled、error 和 selected 状态。

## 3. 布局与响应式

- 从内容关系推导断点，不只套用设备宽度。
- 至少检查窄屏手机、平板/小桌面和宽桌面。
- 避免固定高度截断内容；检查长标题、长单词、数字和本地化文本。
- 确认触控目标尺寸和间距足够，关键操作不会因 hover-only 交互而不可用。
- 在 200% 文本缩放和高缩放率下保持主要流程可用。

## 4. 动效与反馈

- 为动效说明用途：引导注意、解释状态变化、提供反馈或营造与主题一致的氛围。
- 优先设计一个完整的 orchestrated moment，而不是大量无关微动效。
- 主要动画优先使用 transform 与 opacity，避免不必要的布局抖动。
- 使用 `prefers-reduced-motion` 提供静态或简化版本。
- 确保加载、成功、失败、空状态和不可用状态均有清晰反馈。

## 5. 语义与可操作性

- 使用正确的 HTML 元素表达标题、导航、按钮、链接、列表、表单和区域。
- 保持自然、可预测的键盘顺序。
- 为所有交互控件提供清晰的 `:focus-visible` 状态。
- 优先使用原生语义；仅在原生语义不足时增加 ARIA。
- 为图片提供与用途匹配的替代文本；纯装饰图片使用空 alt。
- 检查表单 label、帮助文字、验证提示及错误关联。

## 6. CSS 与组件质量

- 让组件样式边界清晰，避免全局规则意外覆盖局部组件。
- 检查 selector specificity、层叠顺序和重复声明。
- 保持 spacing、radius、shadow、border 和 z-index 使用统一令牌。
- 不用无意义渐变、玻璃拟态、巨型圆角或过度阴影填补缺乏方向的设计。
- 保持组件在内容变化、加载状态和异常状态下稳定。

## 7. 性能与兼容性

- 压缩并正确设置图片尺寸，按需使用响应式图片与延迟加载。
- 避免为小效果引入大型依赖；尊重现有构建系统。
- 检查关键内容在 JavaScript 延迟或失败时的最低可用性。
- 对使用的新 CSS/浏览器特性提供合理回退。

## 8. 交回 Antigravity 前的初步复审

- 在真实浏览器中查看，而不只阅读代码。
- 截图比较桌面与移动视口，检查视觉层级、折行、溢出和留白。
- 用键盘完成主要流程。
- 检查减少动效设置与高对比场景。
- 删除一个最弱、最像模板或不服务主题的装饰元素。
- 记录未运行、未截图或无法验证的项目。
- 列出 Antigravity Stage 3 尚需覆盖的全部路由、视口、语言、状态、交互和外部链接。
